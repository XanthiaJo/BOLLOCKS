The "memory-writer": how new chat becomes stored memories, threads and scene state.

Memory LLM

A second AI that reads new chat and decides what to store. These settings control how it runs.
Extraction profile (required)Which API connection the memory-writer uses (set up under Connection). Smart memory can't run until you pick one — a small/cheap model is usually plenty.
Generation budget (tokens)How much the memory-writer may write per run. ~4 characters ≈ 1 token. Default: 2000. Enter -1 for unlimited — can be slow or expensive on paid APIs.

Extraction

When and how new chat gets turned into stored memories.
Extract after every N new messagesHow often the memory-writer runs. Smaller = more up-to-date but more API calls. Default: 10.
Max stored smart memories (total)Overall cap across all types — oldest are forgotten first. 0 = unlimited. Default: 50.
Caps per memory type — the oldest of that type drop first. 0 = no per-type limit (the total cap still applies). Default: 15 each.
Max per type — factthings that are true
Max per type — eventthings that happened
Max per type — relationshiphow characters feel about each other
Max per type — preferencelikes and dislikes
Prune dormant after N messagesA smart memory that hasn't fired within the last N messages retires itself — moved to Retracted, never deleted, so it can be restored. Canon (no keywords) is exempt. 0 = off; new profiles default to 50 (~5 extraction windows at every=10).
Extraction prompt template

Context threshold (%)Also run extraction early once the chat fills this % of the model's context — so nothing important is lost before old messages get trimmed. Default: 80.

        
Response length (tokens)Fallback reply length — only used when the generation budget above is unset. Usually safe to leave alone. Default: 2000.

Scene state

      A "what is true right now" snapshot — locations, held objects, ongoing conditions. The memory-writer refreshes it wholesale (the old snapshot is discarded); it always injects when present.
      

        
        
Refresh every N extractions1 = refresh every extraction run; higher = cheaper but staler. Default: 1.

        
Max scene entriesCap on snapshot lines kept per chat — the memory-writer's output is trimmed to this. Default: 30.

Injection

      What stored memory spends in each reply's prompt.

      
Budgets

      Token caps on each block of memory text added to a reply's prompt — the totals at the bottom are the worst case and the average per turn.
      

        
Memory injection budgetMax memory text added to each reply's prompt — beyond this, newer memories are left out (oldest are kept). Injects every Nth reply (see refresh rate). Default: 800.

        
Canon injection budgetCanon memories (no trigger keywords) inject every turn at full value — immune to the refresh rate. Default: 800.

        
Thread injection budgetCap on open story-thread context — only spent while threads are open, every turn. Default: 700.

        
Scene injection budgetCap on the live scene-state snapshot — injects every turn while tracking is on. Default: 400.

        
Peak per turnSum of the enabled budgets — the most memory text a single reply can add.

        
Average per turnThe memory block only injects every Nth reply (its refresh rate) — canon, threads and scene inject every turn.
