Smart memory

Memory LLM

The "memory-writer": a second AI that reads new chat and decides what to store. These settings control how it runs.
Extraction profile (required)Which API connection the memory-writer uses (set up under Connection). Smart memory can't run until you pick one — a small/cheap model is usually plenty.
Generation budget (tokens)How much the memory-writer may write per run. ~4 characters ≈ 1 token. Default: 2000. Enter -1 for unlimited — can be slow or expensive on paid APIs.
Injection refresh every N AI messagesOnly add memories to the prompt every Nth reply — saves tokens on the replies in between. 1 = every reply (default).

Extraction

When and how new chat gets turned into stored memories.
Extract after every N new messagesHow often the memory-writer runs. Smaller = more up-to-date but more API calls. Default: 10.
Max stored smart memories (total)Overall cap across all types — oldest are forgotten first. 0 = unlimited. Default: 50.
Caps per memory type — the oldest of that type drop first. 0 = no per-type limit (the total cap still applies). Default: 15 each.
Max per type — factthings that are true
Max per type — eventthings that happened
Max per type — relationshiphow characters feel about each other
Max per type — preferencelikes and dislikes
Extraction prompt template
Custom instructions for the memory-writer (e.g. focus on plot, ignore OOC). Leave blank for the built-in prompt — show it. 

      
      
Context threshold (%)Also run extraction early once the chat fills this % of the model's context — so nothing important is lost before old messages get trimmed. Default: 80.

      
Response length (tokens)Fallback reply length — only used when the generation budget above is unset. Usually safe to leave alone. Default: 2000.

    


    
Injection

Token budgetMax memory text added to each reply's prompt — beyond this, newer memories are left out (oldest are kept). Default: 800.
